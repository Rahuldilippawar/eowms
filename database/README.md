# EOWMS Database — कोणती File कधी वापरायची

खूप सगळ्या वेगळ्या `migration-*.sql` files मुळे गोंधळ होत होता — त्या सगळ्या
आता `migrations-archive/` folder मध्ये (फक्त इतिहास/संदर्भासाठी) ठेवल्या
आहेत. **रोजच्या वापरासाठी फक्त खालच्या 3 files लागतात:**

---

## 1️⃣ नवीन (पहिल्यांदाच) Install करताना

**`schema.sql`** वापरा — यात प्रकल्पातील **सगळे 51 tables एकाच वेळी**,
अगदी अद्ययावत (latest) स्वरूपात आहेत. वेगळी कुठलीही migration चालवायची
गरज नाही.

```
phpMyAdmin -> नवीन रिकामा Database -> Import -> schema.sql निवडा -> Go
```

---

## 2️⃣ आधीच चालू असलेला (जुना डेटा असलेला) Database अद्ययावत करताना

**`RUN-ALL-MIGRATIONS.sql`** वापरा — यात सगळ्या 35 migrations
**बरोबर क्रमाने एकत्र** केलेल्या आहेत. जुना डेटा (staff, कामाच्या नोंदी,
वसतिगृह, वाहन, इ.) **सुरक्षित राहतो** — फक्त नवीन Tables/Columns जोडले
जातात.

```
phpMyAdmin -> तुमचा Live Database -> SQL टॅब -> RUN-ALL-MIGRATIONS.sql
चा संपूर्ण मजकूर पेस्ट करा -> Go
```

⚠️ जर एखादी ओळ "Duplicate column" किंवा "Table already exists" असा Error
देत असेल — घाबरू नका, त्याचा अर्थ ती गोष्ट आधीच झालेली आहे. ती एक ओळ
वगळून उरलेलं चालवा.

---

## 3️⃣ आणीबाणी — Super Admin login हरवला/सगळे Delete झाले तर

**`add-super-admin.sql`** वापरा — संस्था/Super Admin काहीच नसेल तरी हे
आपोआप तयार करतं (सुरक्षित, कधीही चालवता येतं).

---

## 📁 `migrations-archive/` म्हणजे काय?

इथे प्रत्येक feature तयार करताना बनवलेल्या **मूळ, वेगळ्या 35 migration
files** आहेत — आता त्या रोज वापरायची गरज नाही (वरच्या `RUN-ALL-MIGRATIONS.sql`
मध्ये त्या सगळ्या आधीच एकत्र आहेत). फक्त **कधी काय बदल केला होता याचा
इतिहास/संदर्भ** म्हणून ठेवलेल्या आहेत — हवं तर ही संपूर्ण folder डिलीट
केली तरी चालेल, प्रकल्पाच्या कामकाजावर काहीही परिणाम होणार नाही (हे फक्त
SQL संदर्भ-files आहेत, PHP code नाही).
